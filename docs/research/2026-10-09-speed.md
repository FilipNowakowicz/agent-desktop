# Toward human-speed desktop control

Date: 2026-10-09. Measurements from the traces of the
[host browser trial](../trials/2026-10-09-host-browser-task.md) plus proposals.
Only the measurements are evidence; the savings below are estimates to test.

## Where the time goes

Three host sessions (CLI driven by an interactive coding agent, Opus-class
model), from `trace.jsonl`:

| Session | Calls | Wall time | Time inside the tool | Median gap between calls | p90 gap |
| --- | ---: | ---: | ---: | ---: | ---: |
| `ae6efba8cd7e` | 23 | 85 s | 2.2 s (2.6%) | 3.6 s | 6.1 s |
| `3ea87a689fd3` | 46 | 658 s | 2.5 s (0.4%) | 2.3 s | 17.4 s |
| `97d9ba6d2be3` | 95 | 663 s | 4.0 s (0.6%) | 2.1 s | 20.0 s |

Median screenshot 48–155 ms; input calls take milliseconds. **97–99% of the
time is spent outside the tool**: model inference (prefill of images and
context, decoding), the agent's own shell and reading, and occasional human
pauses. Making screenshots or input faster cannot change the result by more than
a few percent.

The loop is also tight: of 59 screenshots, 53 came directly after an input, and
33 followed exactly one action. The agent looked after nearly every step.

So speed = (number of model round trips) × (latency per round trip). A human
clicks about once per second because perception and correction happen without
deliberation; only decisions are deliberate. The goal is the same split: the
model decides, a local loop perceives and corrects at screen speed.

## Ideas, ranked by expected gain per effort

### 1. Act and see in one call (small, near-certain)

Every input returns, after the UI settles, a screenshot or a crop around the
changed area, plus the new focus and title. Settling should be detected from
compositor damage (screencopy reports damaged regions) instead of fixed sleeps,
so the call returns when the frame stops changing, typically 50–300 ms.

Estimate from the trace: 53 of 164 calls (32%) disappear. The changed-region
crop is also smaller than a full frame, which shortens prefill.

### 2. Guarded plans: the model writes the motor program (medium, the big lever)

`desktop_actions` already runs up to 50 steps, but with coordinates or node ids
fixed before the run and only window and focus checks in between. Extend it to
*targets resolved at run time and expectations*:

```text
click text:"Settings"            expect text:"Webhooks" within 2s
click text:"Add webhook"         expect dialog
type  "https://example/hook"
key   Return                     expect text:"Saved"
```

A local executor resolves each target (accessibility names in private sessions;
fast local OCR or template matching of the last frame in host mode, where
accessibility is unavailable), performs the step, waits on damage, checks the
expectation and continues. It returns to the model only at the end or at the
first deviation, with a screenshot of the unexpected state. When things go as
expected, ten steps cost one round trip and run at application speed, i.e.
faster than a person. When they do not, the agent is no worse off than today.

The trace shows runs of up to seven actions between screenshots even now; the
expectation checks make longer runs safe. This also addresses trial finding 2:
an expectation that fails after Ctrl+T reveals a swallowed shortcut at once.

### 3. Replay what worked (medium, faster than human for repeated tasks)

A completed guarded plan, or a trace that ended in a verified outcome, becomes a
named procedure ("install a userscript in Firefox"). Next time it replays with
its expectations as guards and calls the model only on deviation. This joins
the effect atlas line: `desktop_set` already skips the GUI for learned settings,
and halved the cost of three of four settings tasks.

### 4. A fast model for grounding (medium)

Split decide from locate: the main model says "click the Save button in the
webhook dialog"; a small vision model (Haiku-class, or a local grounding model)
returns coordinates and checks the result. Grounding round trips drop to about a
second, and the main model's context stays free of most screenshots.

### 5. Skip pixels where an API exists (varies)

In private sessions, launch browsers with a remote-debugging protocol and act
on the DOM; settings go through `desktop_set`; files through the shell. In the
trial, a DOM view would have prevented the misread stray tab.

### 6. Shorter round trips (small)

Prefer crops and downscaled frames, keep stable context first for prompt
caching, and pre-compute the next observation (OCR, element map) while the model
is thinking, so it is ready when asked.

## Proposed experiment

Build 1 and a minimal 2 (text targets via accessibility in private sessions,
`expect text` / `expect window`, stop on first deviation). Measure on the
existing benchmark tasks with matched arms (several runs per arm, as the effect
ledger study needed): wall time, model round trips, success and wrong-action
rate. Stop criterion: if guarded plans do not cut round trips by at least 30%
without lowering success, keep only act-and-see.
