# Questions only the user can answer

1. **Which two or three tasks would you actually give this desktop each week?** Name the application, input and useful finished result. This determines whether the M3 pilot measures your work rather than invented fixtures. Affects O1/O2/O5 and F001/F020/F029.

2. **Is the next target a dependable personal tool, a public Linux package, or a cross-platform product?** These require different support, documentation and maintenance commitments. Affects O1/O4/O5 and F001/F030/F033.

3. **Whom should the environment protect you from: accidental tool misuse, untrusted web content/apps, or an agent that retains unrestricted host shell access?** The current same-user model cannot enforce secrecy from the last actor. Affects O3, F002/F014/F025 and whether O1 can proceed as a cooperative alpha.

4. **Which accounts, if any, may use dedicated persistent profiles, and what must remain private during takeover?** Select a low-risk initial login and decide whether observation streams/logs should stop. Affects O1/O3 and F002/F023/F024. This question is not permission to access an account.

5. **Which non-Nix distribution and host desktop should be the first supported installation, and what keyboard layout do you use for takeover?** CI containers cannot choose your supported user environment or establish layout usability. Affects O1, F007/F018/F023.

6. **How long should desktops and their screenshots/logs persist, and how much disk space is acceptable?** Choose whether artifacts are disposable by default or deliberately retained. Affects O1/O3 and F013/F035.

7. **Will more than one client or agent operate the same session, or should sessions have one exclusive controller?** A shared session needs an explicit lease and conflict experience; separate desktops may be simpler. Affects O1/O2 and F010/F011.

8. **What failure or intervention rate is acceptable for your work, and which actions are too consequential to retry automatically?** Proposed pilot thresholds in plan.md need your risk and usefulness judgment. Affects O1/O2/O3 and F005/F006/F011/F020.

9. **What separately scoped usage budget, if any, should future model comparisons have?** No paid run was made for this review, and earlier budgets should not become an open-ended authorization. Decide whether call reduction, time, monetary usage or completion matters most. Affects O2/O5 and F008/F021/F022.

10. **How much upstream/runtime maintenance do you want to own, and would you adopt an existing project if it handled your chosen tasks better?** A tiny patch can create a continuing release obligation; ownership and learning may still justify keeping it. Affects O1/O4/O5 and F019/F027/F031–F034.

11. **Does the portable-machine idea solve a current need on hardware you use, or remain an ambition?** A concrete Windows/macOS use case and available test machine would justify a later narrow feasibility study; absence of one favors finishing Linux use first. Affects O4 and F030/F033.
